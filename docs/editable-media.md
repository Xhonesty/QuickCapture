# 声音设备与可继续编辑项目 · v0.11.0

本轮实现限定在 QuickCapture；未提交 Git、未同步或发布 GitHub，旧版 ZIP 保留。当前程序 `dist/QuickCapture.exe`，需整个 dist 文件夹。新版独立便携包在 `artifacts/QuickCapture-win-x64-v0.11.0-local.zip`。

## 声音设备

主窗口保留系统声音、麦克风各自的开关，点击录屏卡片“声音设备…”进入分组窗口。两份列表都有“跟随系统默认设备”，显示 Windows 端点易读名称；指定设备以 WASAPI endpoint ID 保存到 settings.json。刷新不会把缺失设备悄悄换成默认，缺失项和提示保留，选择新项即保存。点击“检测声音”显示录制前的真实电平。

检测使用 NAudio.Wasapi 2.2.1 的共享 WASAPI 输入及播放设备 loopback 数据；录制器仍使用 ScreenRecorderLib，同一份解析后的端点 ID 传给原生录制器。检测独立于媒体编码，不改变录制音频时钟、暂停与恢复。浮点 PCM 峰值经过快速上升/平滑衰减显示，显示宽度使用平方根刻度以便观察低音量。连续 1.5 秒样本峰值至少 95% 时显示 `!` 与过高提示。关闭的音源显示“关”，不会打开对应采集设备。

录制期间控制条在原捕获排除窗口中增加两条电平；设备错误后清零并显示错误。每 700ms 检查端点状态和默认设备变化，检测停止、窗口关闭和录制结束会释放 WASAPI 客户端；异步启动/停止串行化。录制中失去设备或默认设备变化会结束并保存已录内容，状态提示重新选择后开始，避免继续显示正常录音。

“试录 3 秒”只采集已启用的音源，不录屏。分别生成 `Data/AudioTest/microphone.wav`、`system.wav`，通过系统默认播放器分别回放；下一次试录覆盖上一份，窗口提供清理入口。没有电平时需讲话/播放声音再试。没有打开设备时会提示权限与设备不可用，麦克风提示检查 Windows 隐私设置。

参考实现：[NAudio WASAPI capture](https://github.com/naudio/NAudio/blob/v2.2.1/NAudio.Wasapi/WasapiCapture.cs)、[loopback capture](https://github.com/naudio/NAudio/blob/v2.2.1/NAudio.Wasapi/WasapiLoopbackCapture.cs)。依赖、离线包、缓存、许可证全部位于本项目。

## 删除视频中间片段

首尾手柄继续限定外层保留范围。展开“删除中间片段”，在两个输入框填原片起止秒数，或暂停预览后分别点击标记起点/终点，再点击删除。选中列表中的删除项，可调整边界或恢复。Ctrl+Z / Ctrl+Y 及按钮支持本次会话的时间、删除、裁剪、速度和导出设置历史。原片秒数是所有编辑的坐标基准，设置按原片帧率量化；重叠或相邻区间合并，范围钳制到原片，导出至少保留一帧。

时间轴青绿显示外层保留范围，红色覆盖删除项。播放自动跳过删除区间；仍可暂停查看删除范围以精确标记。标签同时显示原片时长、保留时长、按倍率计算的导出时长。小窗口展开删除面板时暂时收起导出设置，折叠后恢复；画面裁剪与删除面板互相避让。

导出按原片顺序分别 trim/atrim，每段重置时间戳，音频补齐/限定到对应视频段长度，concat 后统一应用速度、画面裁剪和帧率。MP4/AAC、WebM/Opus 和 GIF 均走已有验证、进度、取消与临时文件安全替换流程；GIF 无声音。原片始终用于导出，兼容预览副本不参与。

录屏母版的 `Data/Recordings/master-*.mp4.json` 格式新增 `Version: 2` 和可选 `Edit`，Edit 包含原片 Start/End、Deleted、Speed、Mute、Crop、Format、Quality、Fps。旧 JSON 缺这些字段时恢复旧裁剪或完整范围。配置随母版旁边的 JSON 原子写入；外部视频的编辑配置使用 `Data/RecordingEdits/<路径哈希>.json`（文档 Version 1），记录路径、长度和修改时间以拒绝误用已替换视频的配置。配置写入在后台串行执行，关闭等待保存，导出前确认保存成功；失败可点击“保存配置”重试。

使用中段删除或画面裁剪的母版在导出成功后保留；关闭、失败、取消也保留。最近文件的母版可继续编辑，更多菜单的“移到回收站”说明会清理原片与配置；“清理剪辑配置”只恢复编辑设置，保留原片。外部原片不会被自动清理或覆盖。

## 截图项目格式与继续编辑

保存窗口、复制时自动保存及从截图生成的贴图保存，都同步保留项目。导出 PNG/JPG/WebP/BMP 为标准图片，不附加编辑数据。项目在 `Data/ScreenshotProjects/<GUID>.qcap`，为 ZIP 容器：

- `original.png`：无标注的完整底图。
- `project.json`：Owner=`QuickCapture.ScreenshotProject`、Version=1、原片坐标的全部 Annotation、Crop、NextStep、Format、Quality。
- `<导出绝对路径 SHA-256>.link.json`：同一 Owner、关联 Version=1、ExportPath 与 ProjectId。

Annotation 覆盖箭头、五种形状、描边/填充、涂鸦及路径、矩形/画笔马赛克、步骤编号、文字内容/字体/字号/粗体/对齐/文本宽度和颜色透明度。裁剪外标注与原图保留，重新扩大裁剪即可恢复。原图解码后脱离 WPF 解码器元数据，避免重新保存时发生跨线程访问异常。

最近文件的“继续编辑”读取项目，恢复所有对象；可选择、移动、缩放、改文字/编号/样式、删除，新增修改沿用既有撤销重做。历史不跨重启保存，编辑内容跨重启保存。Ctrl+S 更新关联图片与项目并保持重新打开的编辑器；“另存为”或 Ctrl+Shift+S 生成独立关联，并继续编辑新版本。普通图片从最近文件“继续编辑”作为新项目底图打开，首次保存另存新文件。系统默认程序查看入口保留。

项目写入与图片编码在后台，先完整写入新的项目和图片临时文件；图片替换前保留备份，关联提交失败回滚图片。成功关联后再清理旧项目。每个单文件替换使用同目录临时文件和原子移动；失败保留前一份有效图片/项目，若外部锁也阻止回滚，明确报告旧图备份路径并保留该备份。崩溃发生在两个文件提交之间时可能留下待清理备份/孤立项目，不会把它们作为普通图片加入最近文件。

关联、版本、原图、裁剪与对象数据损坏时显示错误并保留文件。未知版本不会覆盖；项目缺失时可恢复对应项目，或清理可确认的失效关联后作为普通图片打开。最近列表扫描已确认关联，所以另存到外部目录的截图也能跨重启找到；再次保存按文件修改时间/长度更新缩略图。

“清理截图项目（保留图片）”说明将失去原图与对象编辑能力，确认后把已确认 Owner、路径关联和 GUID 项目移到回收站。删除关联截图时说明会连同项目移到回收站，仅处理软件确认归属的文件。导出图片本身及其他项目不被项目清理操作删除。

## 验证范围与限制

本机 Windows 单屏 125% DPI。阶段结果与最后汇总见 `artifacts/phase1-results.json`、`phase2-results.json`、`phase3-results.json`、`phase3-restart-results.json`、`audio-pause-results.json`、`reedit-regression-results.json` 及 `editable-media-verification.json`；图件在 `artifacts/screenshots/`。

实际默认/指定端点、播放端点真实 440Hz 音频、电平、短 WAV、设备缺失、释放、两主题、真实暂停恢复与控制条排除均检查。麦克风默认 NVIDIA Broadcast 已打开且有 PCM 数据，本轮未人为讲话，它的采样为静音；回放入口通过系统播放器打开文件，未进行人工听感评价。实体拔插、实际修改默认设备、持续真实过载、多设备混音听感、长时间同步、混合 DPI 多屏仍需人工实机验证。设备缺失与权限拒绝路径已实际触发，未改系统权限或音量。

视频覆盖多个删除段、合并/边界、撤销恢复、实际预览跳过、三种格式与裁剪/1.5×/静音组合、完整解码、颜色序列、音画时长、UI 取消/失败后重试、成功保留母版、恢复及旧元数据。预览由 WPF MediaElement 驱动并约每 80ms 检查跳转，播放时删除边界可能有短暂缓冲；导出使用原片帧边界，项目不合并不同源视频。

截图覆盖所有工具及四格式的恢复像素对比、实际最近菜单与保存/另存为流程、独立进程重启、对象撤销重做、缩略图、关联清理、损坏/缺失/未知版本、模拟提交锁定后的回滚。截图关联与外部视频配置基于本地绝对路径；手动移动/改名后需要恢复原路径，当前不自动寻找移动后的关联。通过应用另存为可建立新关联。数据随运行目录保存，移动便携程序时应同时备份 Data 和所关联图片。

本次不重跑全应用历史套件，不把历史验收当作本轮通过。物理鼠标手柄拖动与系统输入法候选窗完整输入仍保留此前人工复测边界，已使用实际 WPF 控件、路由按钮和媒体视觉验证新增流程。
