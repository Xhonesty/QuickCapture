# 发布验证 · 2026-10-01

验证对象：`dist/QuickCapture.exe`，版本 0.2.0，Windows x64、自包含 .NET 10 发布版。

## 结果

- Release 构建成功，0 警告、0 错误。
- 16 项本机集成检查通过，进程退出码 0；其中 4 项为新增界面检查。
- 当前显示器为单屏、125% 缩放；选区 200 × 100 DIP 对应 250 × 125 物理像素，坐标检查通过。
- 负坐标显示器相对坐标计算与失效显示器拒绝检查通过；未使用真实多屏设备验证。
- 箭头、矩形、文字、马赛克、撤销/重做检查通过。PNG 保持 640 × 400 原始像素，马赛克区域已替换原始像素。
- Windows.Graphics.Capture 桌面及窗口截图检查通过。
- 窗口视频、区域视频、奇数选区启用硬件编码配置、系统声音、麦克风与系统声音混音均生成正式 MP4；停止后未遗留对应临时文件。
- 5 段约 3.2 秒 MP4 全量解码通过，解码退出码均为 0。窗口输出 800 × 500，区域输出 640 × 400；641 × 401 选区输出调整为 640 × 400。
- 系统声音及混音视频包含可完整解码的 AAC 音轨，48 kHz、立体声。
- 主界面、标注编辑器、设置窗口和录制工具条已渲染并目视检查。
- 浅色 / 深色主题双向切换即时生效，设置保存检查通过；浅色主界面、设置、独立编辑器、录制工具条及两种主题的选区已渲染并目视检查。
- 区域截图保留原始屏幕位置；125% DPI 下选区原点及宽高与物理像素一致，导出的 PNG 未包含遮罩、选框或工具栏。
- 工具栏在中心及四周边缘保持可访问；实际底部选区的工具栏移到上方。满屏选择时工具栏保持在屏幕内。
- 原位标注、撤销 / 重做、修改后重新导出、重新框选及工具栏保存操作通过检查。
- 本机默认快捷键存在冲突；首次启动已验证自动使用 `Ctrl+Alt+F8` 截图、`Ctrl+Alt+F9` 录屏。实际快捷键以主界面为准。

集成测试文件在 `dist/Diagnostics/results.json`；媒体检查文件在 `dist/Diagnostics/media-validation.json`，各视频旁保留完整解码日志。界面预览在 `artifacts/screenshots`，原位选区预览使用生成的示例桌面。诊断文件、录音、桌面截图、用户设置均不会进入便携压缩包。

## 验证边界

当前验证覆盖短时录制及本机默认声音设备；未覆盖数小时录制、真实混合 DPI 多屏、设备热插拔、磁盘写满或其他 Windows 版本。麦克风和系统声音的录制管线、音轨生成及解码已验证，未对语音清晰度或长时间音画同步做测量。

## 复现

在普通交互桌面的 PowerShell 中执行：

```powershell
.\tools\build.ps1 -Offline -Test -Microphone
python .\tools\verify-media.py "C:\path\to\ffmpeg.exe"
# 仅复现新增的 4 项界面检查：
.\dist\QuickCapture.exe --self-test --ui-only
```

FFmpeg 仅用于额外的解码验证，程序录屏本身不依赖 FFmpeg。受限的测试进程可能无法访问系统窗口、鼠标或全局快捷键，验证应在普通本机进程中执行。
